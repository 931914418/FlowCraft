# BLOCKING CONSTRAINTS — Read Before Anything Else

> These are not suggestions. Each constraint below was discovered through failure.
> Acknowledge each one explicitly before proceeding.

- [ ] CONSTRAINT: **SSE event names must match between engine and route** — Engine emits `node:${execId}:${nodeId}`, SSE route must listen on `node:${execId}`. Fixed by adding unified event emission in engine.ts. If adding new events, always emit BOTH `node:${execId}:${nodeId}` AND `node:${execId}`.
- [ ] CONSTRAINT: **SSE data format is `event: xxx\ndata: yyy\n\n`** — Frontend must parse event/data as separate lines, NOT try to JSON.parse each line.
- [ ] CONSTRAINT: **No "fixed" claim without browser verification** — CLAUDE.md Step 3 is mandatory: restart service → Ctrl+Shift+R → end-to-end browser test → collect evidence.
- [ ] CONSTRAINT: **nodeOutputs is the single source of truth, variables is a derived view** — Do NOT store stringified output in variables independently. Dual independent storage creates divergence bugs.
- [ ] CONSTRAINT: **Condition V1 expressions cannot be auto-migrated to V2** — Must use dual executor: detect config format and route to V1 or V2 executor.

**Do not proceed until all boxes are checked.**

## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| Premature "fixed" claim | Declaring issue fixed based on curl/API test only, without browser UI verification | blocking | Must follow CLAUDE.md Step 3: restart → refresh → verify user-visible result |
| Dual storage divergence | Writing to nodeOutputs and variables independently | blocking | nodeOutputs = single source, variables = derived getter/proxy |
| AI-generated code nodes | LLM generates workflow with code node → arbitrary JS (RCE) | blocking | Server-side validation: reject AI-generated workflows containing code nodes |
| Falsy check in DB upsert | `tokens ? { tokens } : {}` loses tokens=0 | advisory | Use `tokens !== undefined ? { tokens } : {}` |
