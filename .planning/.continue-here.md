# BLOCKING CONSTRAINTS — Read Before Anything Else

> These are not suggestions. Each constraint below was discovered through failure.
> Acknowledge each one explicitly before proceeding.

- [ ] CONSTRAINT: **SSE event names must match between engine and route** — Engine emits `node:${execId}:${nodeId}`, SSE route must listen on `node:${execId}`. Fixed by adding unified event emission in engine.ts. If adding new events, always emit BOTH `node:${execId}:${nodeId}` AND `node:${execId}`.
- [ ] CONSTRAINT: **SSE data format is `event: xxx\ndata: yyy\n\n`** — Frontend must parse event/data as separate lines, NOT try to JSON.parse each line. The previous parser split on `:` and tried to parse the right side as JSON, which failed on `event: status` lines.
- [ ] CONSTRAINT: **No "fixed" claim without browser verification** — User caught premature claims multiple times. CLAUDE.md Step 3 is mandatory: restart service → Ctrl+Shift+R → end-to-end browser test → collect evidence.
- [ ] CONSTRAINT: **nodeOutputs is the single source of truth, variables is a derived view** — Do NOT store stringified output in variables independently. Variables should be computed from nodeOutputs on access. Dual independent storage creates divergence bugs (autoplan eng review finding).
- [ ] CONSTRAINT: **Condition V1 expressions cannot be auto-migrated to V2** — V1 uses flat variables map (`input.count`), V2 uses node-scoped `{ sourceNodeId, path }`. There is no deterministic mapping. Must use dual executor: detect config format and route to V1 or V2 executor.

**Do not proceed until all boxes are checked.**

## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| Premature "fixed" claim | Declaring issue fixed based on curl/API test only, without browser UI verification | blocking | Must follow CLAUDE.md Step 3: restart → refresh → verify user-visible result via agent-browser |
| Inferred functionality | Claiming features work without testing them | blocking | Test before documenting. Mark untested items explicitly |
| Dual storage divergence | Writing to nodeOutputs and variables independently, causing downstream nodes to read different values | blocking | nodeOutputs = single source, variables = derived getter/proxy |
| AI-generated code nodes | LLM generates workflow with code node → arbitrary JS executes on server (RCE) | blocking | Server-side validation: reject any AI-generated workflow containing code type nodes |
| Falsy check in DB upsert | Using `tokens ? { tokens } : {}` loses tokens=0 for non-LLM executors | advisory | Use `tokens !== undefined ? { tokens } : {}` |
