# BLOCKING CONSTRAINTS — Read Before Anything Else

> These are not suggestions. Each constraint below was discovered through failure.
> Acknowledge each one explicitly before proceeding.

- [ ] CONSTRAINT: **Start 节点必须将 input 数据作为 output 传递** — engine.ts 中 start 节点之前返回 null，导致 Condition V2 无法从上游取值。已修复为 `return { output: context.variables.get('input'), tokens: 0 }`。如重构 start 节点，必须保留此行为。
- [ ] CONSTRAINT: **nodeOutputs 是单一数据源，variables 是派生视图** — 不要在两个 map 中独立存储相同数据。resolveVariable 函数处理 `.output` 后缀查找。任何新执行器必须从 nodeOutputs 取上游数据。
- [ ] CONSTRAINT: **Condition V1 表达式不能自动迁移到 V2** — 必须用双执行器：检测 config 中有 field+operator 走 V2，只有 expression 走 V1。
- [ ] CONSTRAINT: **CodeExecutor 需要 ENABLE_CODE_EXECUTION=1 环境变量** — new Function() 存在 RCE 风险，默认禁用。
- [ ] CONSTRAINT: **Webhook 数据必须写入独立数据库列** — webhookPath/webhookSecret 存在 definition JSON 内部的同时，必须通过 INSERT/UPDATE 写入独立列。webhook 路由通过独立列查询。
- [ ] CONSTRAINT: **Webhook secret 必须使用 timingSafeEqual 比较** — 禁止用 `!==` 或 `===` 直接比较。

**Do not proceed until all boxes are checked.**

## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| Premature "fixed" claim | 声称修复仅基于 curl/API 测试，无浏览器验证 | blocking | CLAUDE.md Step 3: restart → refresh → 端到端浏览器验证 |
| Dual storage divergence | 在 nodeOutputs 和 variables 中独立写入相同数据 | blocking | nodeOutputs = single source, variables = derived via resolveVariable |
| AI-generated code nodes | LLM 生成包含 code 节点的工作流 → RCE | blocking | 简单模式过滤 + 服务端 VALID_NODE_TYPES 白名单 + ENABLE_CODE_EXECUTION 环境变量 |
| Start node null output | start 节点返回 null 导致下游 Condition 无法取值 | blocking | start 节点必须返回 input 作为 output |
| Webhook column mismatch | webhook 数据只存 JSON 不存独立列，路由查不到 | blocking | INSERT/UPDATE 时必须同时写入独立列 |
| Falsy check in DB upsert | `tokens ? { tokens } : {}` 丢失 tokens=0 | advisory | 用 `tokens !== undefined ? { tokens } : {}` |
