# FlowCraft v2 — AI 原生工作流自动化平台

> 日期：2026-05-18
> 状态：设计完成，待实施

## 1. 产品定位

**一句话：** 用自然语言描述需求，AI 帮你搭建和执行自动化工作流。

**核心变化：** 从"拖节点 + 写代码"的工具，升级为"说需求 + AI 编排"的平台。

**目标用户：**
- 主要：不会写代码但需要自动化的业务人员（运营、产品、内容创作者）
- 次要：想要快速原型的开发者

**差异化方向：** AI 原生。不是"有一个 AI 节点"，而是 AI 贯穿整个产品——创建、配置、处理、调试、优化。

## 2. 双模式设计

**简单模式（默认）：**
- 可视化节点 + AI 处理 + 自然语言配置
- 不出现任何代码
- 数据处理通过"数据映射"和"AI 处理"两个节点完成

**高级模式（按节点升级）：**
- 节点可切换为代码编辑器
- 完整 JavaScript 编程能力
- 简单模式和高级模式可以在同一个工作流中共存

**切换机制：节点级渐进**
- 默认简单模式
- 用户可以随时将单个节点"升级"到高级模式
- 不需要提前选择模式，自然学习

## 3. 节点系统

### 触发类

| 节点 | 模式 | 说明 |
|------|------|------|
| Start | 简单/高级 | 手动触发，保留现有功能 |
| Webhook | 简单/高级 | 新增。外部事件触发，生成唯一 URL |

### 动作类

| 节点 | 模式 | 改动 |
|------|------|------|
| HTTP | 简单/高级 | 保留，加测试按钮、URL 校验、Headers 辅助 |
| LLM | 简单/高级 | 保留，增加快捷模板（翻译、摘要、分类等） |

### 处理类

| 节点 | 模式 | 说明 |
|------|------|------|
| 数据映射 | 简单/高级 | 新增。可视化字段选择、重命名、格式转换 |
| AI 处理 | 简单/高级 | 新增。自然语言描述数据处理需求，LLM 执行 |
| Code | 仅高级 | 降级。JavaScript 代码编辑器，简单模式不显示 |

### 控制类

| 节点 | 模式 | 改动 |
|------|------|------|
| Condition | 简单/高级 | 改为可视化：选字段 + 选操作符 + 填值 |
| End | 简单/高级 | 保留现有功能 |

### 节点总数

- 简单模式：7 个（Start、Webhook、HTTP、LLM、数据映射、AI 处理、Condition、End）
- 高级模式：8 个（多一个 Code）

## 4. 数据映射节点

替代简单场景下的 Code 节点，覆盖 80% 的数据处理需求。

**功能：**
1. 自动解析上游数据结构——从实际输出中提取字段列表
2. 勾选要保留的字段，取消丢弃
3. 字段重命名（name → username）
4. 格式转换（日期、数字、大小写）
5. "AI 帮我选字段"按钮——描述需求，AI 自动选中

**界面：**
- 上方：上游数据预览（树形结构，支持嵌套）
- 中间：勾选框 + 重命名输入框
- 下方：输出预览
- 按钮：添加自定义字段 / AI 帮我选字段

**实现关键：**
- 首次配置时用占位符，执行一次后自动填充真实数据
- 上游执行完后才能拿到数据结构，需要缓存上次执行的输出

## 5. Condition 节点可视化

**当前：** 写表达式 `input.count > 5`

**改为：**
1. 字段：从上游实际数据中提取，下拉选择
2. 比较操作符：下拉选择（等于/不等于/大于/小于/包含/为空）
3. 值：文本输入

三步操作，不需要写任何代码。

## 6. AI 助手

编辑器顶部的对话框，贯穿全局。

**能力：**

1. **自动生成工作流** — 描述需求，AI 生成节点 + 边 + 配置
2. **配置自动补全** — 点击节点时，AI 根据上下文推荐参数
3. **调试助手** — 执行失败时分析原因并建议修复
4. **优化建议** — 分析工作流结构，建议合并或优化

**实现策略：**
- 复用已有 LLM 节点能力，不做独立大模型调用
- AI 助手 prompt 固定，包含节点类型清单和配置规则
- 返回结构化 JSON（节点列表 + 边列表 + 配置），前端直接渲染

## 7. Webhook 触发

**新增路由：** `POST /api/hooks/:hookId`

**流程：**
1. 用户在工作流中添加 Webhook 触发器
2. 系统生成唯一 URL（如 `/api/hooks/abc123`）
3. 外部系统调用该 URL 时，自动执行工作流
4. 请求 body 作为工作流输入数据

**替代定时触发：**
- 不自建调度器
- 用户可用外部服务（cron-job.org、GitHub Actions）定时调 Webhook

## 8. HTTP 节点改进

保留通用设计，增加辅助功能：
- URL 格式校验
- Headers 自动补全 Content-Type
- Body JSON 格式化和校验
- **测试按钮** — 发送请求并预览响应数据，不需要跑整个工作流

## 10. 分期优先级

**先做什么：**
1. Condition 可视化（改动最小，体验提升最大）
2. HTTP 测试按钮（解决最大痛点）
3. 数据映射节点（解决 Code 节点门槛问题）
4. Webhook 触发（从玩具变工具）
5. AI 助手（核心差异化）

**后做什么：**
- LLM 快捷模板
- AI 配置补全
- AI 调试助手
- 简单/高级模式 UI 切换
